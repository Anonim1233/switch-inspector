# Описание компонентов системы

Назначение, ответственность, зависимости и известные ограничения
каждой части.

---

## Обзор

| Компонент | Технология | Копий | Хранит состояние |
|---|---|:---:|:---:|
| Интерфейс | React 18, отдаётся статикой | 2+ | нет |
| Сервер приложения | Node.js 22, Express 4 | 2+ | нет |
| База данных | PostgreSQL 13+ | 1 | да |
| Точка входа | Контроллер кластера | — | нет |

**Состояние сосредоточено в базе.** Всё, что должно переживать
перезапуск и быть общим для копий, вынесено туда: данные, состояние
входа, счётчики попыток. Копии приложения взаимозаменяемы.

---

## Интерфейс

### Назначение

Весь пользовательский интерфейс: шесть разделов, вход, личный кабинет,
управление доступом.

### Ответственность

| Отвечает | Не отвечает |
|---|---|
| Отображение данных | Проверка прав — только подсказка интерфейсу |
| Разбор файлов Excel и CSV | Хранение данных |
| Формирование печатных форм | Бизнес-правила — дублируются на сервере |
| Локальное состояние экранов | Достоверность показываемого |

> **Проверки прав в интерфейсе — не защита.** Они лишь отключают
> недоступные действия, чтобы пользователь не упирался в отказ.
> Настоящая проверка выполняется на сервере при каждом запросе.

### Устройство

| Слой | Где | Что содержит |
|---|---|---|
| Обращения к серверу | `src/api/` | Единая точка запросов, поток обновлений |
| Правила предметной области | `src/domain/` | Чистые функции без привязки к интерфейсу |
| Состояние | `src/store/` | Шесть областей данных |
| Общие части | `src/components/` | Оболочка, вход, переиспользуемые элементы |
| Разделы | `src/features/` | По папке на раздел |

**Правила предметной области вынесены отдельно** и не зависят от
интерфейса: их можно проверить тестами и переиспользовать. Именно
они покрыты автоматическими проверками.

### Зависимости

| Библиотека | Для чего | Заменяема |
|---|---|---|
| `react`, `react-dom` | Построение интерфейса | нет |
| `@reduxjs/toolkit`, `react-redux` | Общее состояние | сложно |
| `react-router-dom` | Адреса разделов | да |
| `chart.js`, `react-chartjs-2` | Графики | да |
| `xlsx` | Чтение и запись таблиц | сложно |
| `qrcode` | Коды для наклеек | да |

### Известные ограничения

| Ограничение | Значимость |
|---|---|
| Формула подсчёта замечаний продублирована на сервере | Требует ручной синхронизации |
| Список коммутаторов загружается целиком | При росте вдесятеро потребуется постраничная выдача |
| Данные раздела «Оборудование» живут только в памяти | Теряются при перезагрузке страницы — так задумано |

## Сервер приложения

### Назначение

Обработка запросов, проверка прав, формирование отчётов, рассылка
изменений между пользователями.

### Ответственность

| Отвечает | Не отвечает |
|---|---|
| Проверка прав — окончательная | Отображение |
| Целостность данных | Резервное копирование |
| Разграничение по зоне ответственности | Выпуск сертификатов |
| Формирование отчёта | Сбор журналов |

### Функциональные блоки

| Блок | Что делает |
|---|---|
| Слой доступа к данным | Пул соединений, подстановка параметров, транзакции |
| Защита запросов | Заголовки, ограничение частоты, проверка токена |
| Проверка личности | Единая точка — заменяется при переходе на корпоративный вход |
| Разграничение доступа | Роли и зона ответственности |
| Предметная логика | Коммутаторы, шкафы, дивизионы, заметки |
| Отчётность | Формирование документа со встраиванием шрифта |
| Уведомления | Публикация и приём событий через базу |
| Журнал действий | Фиксация изменений: кто, что, когда, с какого адреса |

### Точки расширения

| Что менять | Где |
|---|---|
| Способ входа | `verifyCredentials` — одна функция |
| Правила подсчёта замечаний | `ISSUE_COUNT_SQL` **и** `domain/issues.js` |
| Новый раздел данных | Новая таблица, новые адреса, срез состояния |
| Правила доступа | `requireEdit`, `requireUnrestrictedDeveloper`, `checkMagScope` |
| Новое событие журнала | Вызов `writeAudit` в нужном месте |

### Известные ограничения

| Ограничение | Значимость |
|---|---|
| Ограничение частоты считается в памяти каждой копии | Предел умножается на число копий |
| Токен потока обновлений передаётся в адресе | Попадает в журналы прокси |
| Токен действует 30 дней без возможности отзыва | При смене пароля старые остаются рабочими |

Подробнее — в [разборе защищённости](../Подготовка-к-проверке-защищённости.md).

## База данных

### Назначение

Единственное хранилище состояния системы.

### Что хранит

| Группа | Таблицы |
|---|---|
| Учёт оборудования | `switches`, `cabinets`, `cabinet_items` |
| Совместная работа | `notes`, `statuses` |
| Организационная структура | `divisions`, `division_mags` |
| Доступ | `users`, `user_divisions` |
| Служебное | `oauth_states`, `login_attempts` |

Помимо данных выполняет две задачи, обычно решаемые отдельными
средствами:

- **Общее состояние копий приложения** — счётчики и состояние входа
- **Канал уведомлений** — рассылка изменений между копиями

### Особенности

**Объект хранится без префикса** (`134`), имя коммутатора — с ним
(`MAG134_70`). Полный вид собирается приложением.

**Разделитель в именах непостоянен**: встречаются и `DS253_66`,
и `DS253-67`. Сопоставление приводит обе стороны к единому виду.

**Способ входа задаётся полем**, а не наличием пароля.

### Известные ограничения

| Ограничение | Значимость |
|---|---|
| Внешние ключи не объявлены по умолчанию | Целостность держится на коде |
| Аватары хранятся в самой базе | Приемлемо при нынешнем числе пользователей |
| Отметки времени числом, а не типом даты | Лишает встроенных средств работы с датами |

Команды для добавления связей: `database/03-constraints.sql`.

## Точка входа

### Назначение

Приём обращений снаружи, распределение по частям приложения,
шифрование соединения.

### Требования

| Требование | Почему |
|---|---|
| Передавать адрес клиента заголовком | Иначе все клиенты определяются как один, и ограничение частоты становится общим |
| Не буферизовать поток событий | Иначе живые обновления не доходят |
| Длительное время ожидания для потока | Соединение держится открытым долго |

## Внешние системы

| Система | Направление | Состояние |
|---|---|---|
| Keycloak | Приложение → Keycloak | **Реализовано** — основной способ входа |
| NetBox | Приложение → NetBox | **Реализовано, только чтение** — отбор по состоянию `active` |

> **Обмен с NetBox односторонний.** По решению сетевого отдела
> приложение только читает данные. Расхождения показываются списком,
> исправления вносятся в той системе, где находится источник истины.

## Матрица зависимостей

| Компонент | Зависит от | Что произойдёт при отказе |
|---|---|---|
| Интерфейс | Сервер | Показывает ошибку связи, ранее загруженное остаётся |
| Сервер | База | Не запускается либо отвечает отказом |
| Сервер | Keycloak | Вход невозможен — нужны аварийные записи с паролем |
| База | — | Приложение неработоспособно |

> **Отказ Keycloak оставляет систему без входа.** Поэтому в плане
> перехода предусмотрено сохранение одной-двух записей с локальным
> паролем.

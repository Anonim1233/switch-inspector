# Схема взаимодействия компонентов

Последовательность обмена для ключевых сценариев. Показаны те, где
логика неочевидна и где ошибка при доработке наиболее вероятна.

---

## 1. Вход в систему

```mermaid
sequenceDiagram
    participant Б as Браузер
    participant I as Ingress
    participant П as Приложение
    participant БД as PostgreSQL

    Б->>I: POST /api/login
    I->>П: Проксирует, добавляет адрес клиента
    П->>БД: Счётчик попыток по паре «адрес и логин»
    БД-->>П: Число попыток

    alt Превышено
        П-->>Б: 429 с указанием времени ожидания
    else Допустимо
        П->>БД: Поиск учётной записи
        Note over П: Сравнение пароля выполняется ВСЕГДА,<br/>даже если записи нет — иначе время<br/>ответа выдало бы существующие логины
        П->>БД: Сброс счётчика для этой пары
        П-->>Б: Токен, роль, зона ответственности
    end
```

**Ключевое:** счётчик ведётся по паре «адрес и логин». Если считать
только по адресу, ограничение обходится: имея одну действующую запись,
можно чередовать подбор чужого пароля с входом под своей.

## 2. Запрос данных с проверкой прав

```mermaid
sequenceDiagram
    participant Б as Браузер
    participant П as Приложение
    participant БД as PostgreSQL

    Б->>П: GET /api/switches (токен в заголовке)
    П->>П: Проверка подписи токена
    П->>БД: Чтение пользователя
    Note over П,БД: Перечитывается на КАЖДОМ запросе:<br/>понижение роли действует немедленно,<br/>а не после истечения токена
    БД-->>П: Роль, отображаемое имя

    П->>БД: Зона ответственности пользователя
    БД-->>П: Список дивизионов либо пусто

    alt Ограничений нет
        П->>БД: SELECT без фильтра по объектам
    else Зона задана
        П->>БД: SELECT с фильтром по доступным объектам
    end
    БД-->>П: Записи
    П-->>Б: Данные с русскими ключами
```

**Ключевое:** ограничение применяется в самом запросе к базе, а не
фильтрацией результата. Отдать лишнее и отфильтровать потом означало бы,
что данные всё равно покидали хранилище.

## 3. Живые обновления между копиями приложения

```mermaid
sequenceDiagram
    participant Б1 as Браузер А
    participant К1 as Копия 1
    participant БД as PostgreSQL
    participant К2 as Копия 2
    participant Б2 as Браузер Б

    Note over К1,К2: При запуске каждая копия подписывается<br/>на канал уведомлений

    Б1->>К1: POST /api/notes
    К1->>БД: Проверка зоны ответственности
    К1->>БД: Запись заметки
    К1->>БД: Публикация уведомления

    БД-->>К1: Уведомление
    БД-->>К2: Уведомление

    Note over К2: Проверяет зону КАЖДОГО подключённого:<br/>событие по чужому дивизиону не отправляется

    К2-->>Б2: Событие потоком
    Note over Б2: Изменение видно без перезагрузки
```

**Почему через базу.** Соединения держит конкретная копия приложения.
Без общего канала пользователь на первой копии не увидел бы правок
того, кто попал на вторую. Отдельного посредника не потребовалось —
подошёл встроенный механизм уведомлений PostgreSQL.

**Зона проверяется при рассылке.** Иначе поток отдавал бы то, что
обычные запросы не отдают.

## 4. Сохранение содержимого шкафа

```mermaid
sequenceDiagram
    participant Б as Браузер
    participant П as Приложение
    participant БД as PostgreSQL

    Б->>П: PUT /api/cabinets/{id}/items
    П->>БД: Шкаф и его объект
    П->>П: Проверка зоны ответственности

    П->>БД: BEGIN (выделенное соединение)
    П->>БД: Удаление всех позиций шкафа
    loop По каждой позиции
        П->>БД: Вставка позиции
    end
    П->>БД: COMMIT

    П->>БД: Сверка с учётом коммутаторов
    БД-->>П: Отметки о расхождениях
    П->>БД: Публикация уведомления
    П-->>Б: Содержимое с отметками
```

**Транзакция на выделенном соединении.** В пуле соединений отдельные
команды начала и завершения могут уйти в разные соединения — тогда
откат при ошибке не сработает, и шкаф остался бы наполовину пустым.

**Содержимое заменяется целиком.** Это отражает то, как заполняется
монтажный чертёж, но означает: при одновременном редактировании одного
шкафа двумя людьми второе сохранение затрёт первое. Известное
ограничение.

## 5. Сопоставление коммутатора со шкафом

```mermaid
sequenceDiagram
    participant П as Приложение
    participant БД as PostgreSQL

    П->>БД: Все коммутаторы объекта
    БД-->>П: Список имён

    loop По каждой позиции шкафа
        Note over П: 1. Прямое вхождение имени<br/>«Коммутатор DS253_72» → «DS253_72»
        Note over П: 2. Если не нашлось — по номеру<br/>«SW_72» → любое имя, кончающееся на 72
        Note over П: Разделитель приводится к единому виду:<br/>в данных встречаются и «_», и «-»
        П->>П: Сравнение шкафа из учёта с текущим
    end

    П-->>П: Отметки: найден, расхождение, фактический шкаф
```

**Почему поиск, а не сборка имени.** Собрать ожидаемое имя как
«объект и номер» нельзя: объект хранится без префикса, имя —
с префиксом, и угадывать его ненадёжно. Поэтому берутся все
коммутаторы объекта и сравнение идёт по вхождению.

**Почему не средствами базы.** Символ подчёркивания в шаблоне поиска
базы означает «любой один символ», и шаблон совпал бы с посторонними
именами. Сравнение выполняется в приложении.

## 6. Формирование отчёта

```mermaid
sequenceDiagram
    participant Б as Браузер
    participant П as Приложение
    participant БД as PostgreSQL

    Б->>П: GET /api/reports/management.pdf
    П->>П: Проверка роли: только разработчик
    П->>БД: Зона ответственности
    П->>БД: Показатели с учётом зоны
    П->>БД: Разбивка по дивизионам
    П->>БД: Проблемные объекты

    Note over П: Встраивание шрифта с кириллицей:<br/>встроенные шрифты формата её не содержат,<br/>первая же русская буква даёт ошибку

    П-->>Б: Документ PDF
```

**Отчёт учитывает зону ответственности.** Руководитель дивизиона
получает документ только по своим объектам — отдельного действия
для этого не требуется.

## 7. Фиксация изменения в журнале

```mermaid
sequenceDiagram
    participant Б as Браузер
    participant П as Приложение
    participant БД as PostgreSQL

    Б->>П: POST /api/switches
    П->>П: Проверка прав и зоны ответственности
    П->>БД: Чтение прежнего состояния записи
    П->>БД: Сохранение изменений

    Note over П: Сравнение: какие поля изменились

    alt Изменения есть
        П->>БД: Запись в журнал: поле, было, стало
    else Изменений нет
        Note over П: В журнал не пишется — пустые записи<br/>сделали бы его нечитаемым
    end

    П->>БД: Публикация уведомления
    П-->>Б: Сохранённая запись
```

**Фиксируются только изменённые поля.** Запись строки целиком сделала
бы журнал непригодным для чтения: при разборе случая пришлось бы
сравнивать записи глазами.

**Сбой записи в журнал не отменяет операцию.** Если журнал недоступен,
действие всё равно выполняется, а причина попадает в вывод сервера:
потерять данные хуже, чем потерять запись о них.

## 8. Получение данных из NetBox

```mermaid
sequenceDiagram
    participant Б as Браузер
    participant П as Приложение
    participant NB as NetBox

    Б->>П: GET /api/netbox/devices
    П->>NB: Запрос с отбором:<br/>status=active и роли коммутаторов

    loop Пока есть страницы
        NB-->>П: Часть устройств и адрес следующей
        П->>П: Пауза перед следующим обращением
    end

    П->>П: Приведение к виду выгрузки
    П-->>Б: Устройства

    Note over Б: Сверка с учётом выполняется<br/>в браузере на уже загруженных данных
```

**Отбор выполняет NetBox**, а не приложение: устройства в других
состояниях не приходят вовсе. Иначе сверка показывала бы расхождения
по оборудованию, которого фактически нет в работе.

**Постраничный обход обязателен.** NetBox отдаёт устройства частями,
и без обхода до конца часть данных терялась бы молча.

**Обмен односторонний** — запись не выполняется по решению сетевого
отдела.

## Сводная таблица обмена

| Направление | Способ | Что передаётся |
|---|---|---|
| Браузер → Ingress | HTTPS | Запросы интерфейса и API |
| Ingress → Приложение | HTTP | Проксирование, адрес клиента в заголовке |
| Приложение → PostgreSQL | Протокол базы | Чтение и запись данных |
| Приложение → PostgreSQL | Уведомление | Публикация события об изменении |
| PostgreSQL → все копии | Подписка | Доставка события |
| Приложение → Браузер | Поток событий | Уведомление об изменении |
| Приложение → Keycloak | HTTPS | Проверка личности при входе |
| Приложение → NetBox | HTTPS | Выгрузка устройств, только чтение |
| Приложение → PostgreSQL | Протокол базы | Запись в журнал действий |
